# CyberDeck

A modular, gamified network infiltration and intrusion countermeasure simulator built in Python using Object-Oriented Programming (OOP) principles. Developed as the Major Project for **Scripting 4.1** in the **BEng (Hons) in Computer Engineering with Robotics** programme at **TUS Athlone**.

---

## Overview

In enterprise computer networking and penetration testing, operators execute systematic attack lifecycles: reconnaissance, vulnerability identification, exploitation, lateral pivoting across subnets, and data exfiltration. At the same time, defensive network intrusion detection systems (IDS) actively monitor network traffic and trigger Intrusion Countermeasure Electronics (ICE) to trace and sever unauthorized connections.

**CyberDeck** simulates these concepts within an interactive terminal environment. The player operates a simulated hardware cyberdeck with finite RAM and CPU processing threads, deploying modular intrusion programs across a directed network graph while managing defensive detection risk.

The project is completely self-contained within Python's standard library—requiring zero external package installations.

---

## Key Features & Architecture

* **Graph-Based Network Pivoting**: Networks are modelled as directed topologies using `NetworkNode` and `NetworkGraph`. Deep subnet servers cannot be accessed until intermediate gateways and proxies are exploited.
* **Hardware Resource Scheduling**: The `CyberDeck` hardware manager enforces finite RAM capacity and CPU core concurrency limits, preventing overload and automatically reclaiming memory upon program completion.
* **Polymorphic Program Hierarchy**: Extensible `BaseProgram` class hierarchy powering reconnaissance (`PortScanner`), exploitation (`BruteForcer`), and exfiltration (`DataExtractor`).
* **Reactive Intrusion Countermeasures (ICE)**: The `TraceEngine` monitors network noise generated by active programs. Crossing detection thresholds triggers alarms and defensive daemons (such as `TraceAcceleratorIce` and `FirewallLockIce`), locking servers and racing the player to 100% trace saturation.
* **Decoupled Terminal HUD**: The `TerminalUI` renders an ASCII dashboard with live telemetry meters, dynamic network topology status tables, active program progress bars, and an infiltration event log stream.
* **Scenarios & Full State Persistence**: The `ScenarioLoader` validates external JSON campaign files and provides round-trip save/load game persistence.

## Quick Start & Installation

CyberDeck requires **Python 3.10+** and uses only standard library modules.

### 1. Launching the Simulator

To launch the default mission scenario (**Operation Iron Gate**):

```bash
# From the cyberdeck/ directory:
python3 main.py

# Or from the repository root:
python3 cyberdeck/main.py
```

### 2. Loading a Custom Scenario

You can pass any scenario JSON file directly on the command line:

```bash
python3 main.py scenarios/shadow_grid.json
```

### 3. Resuming a Saved Game

```bash
python3 main.py --load savegame.json
```

## How to Play

### Mission Objective
Your mission is to infiltrate the target network, pivot across protected subnet tiers, locate the central secure database vault, and extract the confidential data payload **before the defensive trace reaches 100%**.

### Gameplay Lifecycle

```text
┌────────────────┐     ┌──────────────┐     ┌────────────────┐     ┌──────────────┐
│  1. RECON      │ ──> │ 2. EXPLOIT   │ ──> │ 3. PIVOT       │ ──> │ 4. EXTRACT   │
│  scan <ip>     │     │ crack <ip> <p>│    │ (unlock deeper)│     │ extract <ip> │
└────────────────┘     └──────────────┘     └────────────────┘     └──────────────┘
```

1. **Step 1: Reconnaissance (Port Scanning)**
   * Inspect the **Network Topology** table on your HUD.
   * Target nodes reachable from your current entry point will display `REACHABLE: YES`.
   * Deploy a scanner on a reachable node:
     ```text
     cyberdeck> scan 10.0.0.1
     ```
   * Advance the simulation clock using the `tick` command:
     ```text
     cyberdeck> tick 2
     ```
   * Once the scanner completes, the node moves to the `PROBED` state, revealing its closed and open ports.

2. **Step 2: Exploitation (Cracking Access)**
   * Deploy a brute-forcer against a closed port on the probed server:
     ```text
     cyberdeck> crack 10.0.0.1 80
     ```
   * Advance the simulation:
     ```text
     cyberdeck> tick 2
     ```
   * When all ports on a machine are cracked, the node's firewall is bypassed, transitioning its status to `EXPLOITED`.

3. **Step 3: Lateral Movement (Pivoting)**
   * Once a machine is `EXPLOITED`, your cyberdeck can pivot through it to reach deeper internal hosts on adjacent subnets.
   * Nodes connected to the compromised machine will now show `REACHABLE: YES`. Repeat scanning and cracking on these deeper hosts.

4. **Step 4: Exfiltration (Stealing the Objective)**
   * Once the central vault host (e.g. `10.0.0.3` or `10.0.1.100`) is in the `EXPLOITED` state, deploy the exfiltration tool:
     ```text
     cyberdeck> extract 10.0.0.3
     cyberdeck> tick 3
     ```
   * When the extractor reaches 100%, the confidential payload is exfiltrated and you achieve **Mission Victory**!

### Resource & Trace Management
* **RAM Allocation**: Your CyberDeck has finite RAM (e.g. 8 MB or 12 MB). Each program reserves RAM while executing (`PortScanner` = 2 MB, `BruteForcer` = 3 MB, `DataExtractor` = 4 MB). Resources are automatically returned to your pool when programs complete or when aborted.
* **CPU Core Concurrency**: You can only run as many concurrent programs as you have available CPU cores.
* **Defensive Noise & ICE**: Every active program generates network noise that accelerates defensive detection. If trace crosses 50%, defensive alarms trigger, multiplying detection speed. If trace crosses 80-85%, defensive ICE daemons may lock down target servers.
* **Game Over**: If the defensive trace reaches 100.0%, your connection is severed by defensive countermeasure systems (**Mission Failure**).

## Interactive Command Reference

| Command | Arguments | Description |
| :--- | :--- | :--- |
| `scan` | `<ip>` | Deploys a `PortScanner` on a reachable machine to discover ports. |
| `crack` | `<ip> <port>` | Deploys a `BruteForcer` to crack open a specific port. |
| `extract` | `<ip>` | Deploys a `DataExtractor` to exfiltrate confidential files from an exploited node. |
| `abort` | `<name_or_ip>` | Aborts a running program immediately and reclaims its allocated RAM. |
| `tick` | `[n]` | Advances the simulation clock by `n` turns (default: 1 turn). |
| `status` | | Refreshes the terminal telemetry dials and network topology table. |
| `save` | `[filepath]` | Serialises the current game state to a JSON save file (default: `savegame.json`). |
| `load` | `[filepath]` | Restores and resumes a saved game from disk. |
| `scenario` | `<filepath>` | Loads a new mission campaign JSON file on the fly. |
| `help` | | Displays the available command reference and syntax guide. |
| `exit` / `quit` | | Gracefully disconnects and terminates the simulation. |

The test suite covers the domain model, graph routing, process scheduler, defensive daemons, terminal rendering, scenario validation, and save/load persistence.

## Assessment Alignment

This codebase satisfies all criteria for the **Scripting 4.1 Major Project (70% Software Deliverable)**:

* **Authentic Object-Oriented Design**: Pure OOP structure where natural entities (`NetworkNode`, `NetworkGraph`, `CyberDeck`, `BaseProgram`, `TraceEngine`, `TerminalUI`, `ScenarioLoader`) encapsulate cohesive state (what they know) and behaviour (what they do).
* **Inheritance & Polymorphism**: Abstract base classes (`BaseProgram`, `BaseIceDaemon`) with specialized subclasses using the Strategy pattern for tool execution and defensive reaction.
* **Object Composition**: Graphs composing nodes, decks holding active programs, sessions orchestrating engines, and daemons protecting specific network hosts.
* **Input Validation & Error Handling**: Robust defensive programming guarding against invalid inputs and system exceptions (`ValueError`, `TypeError`, `PermissionError`, `KeyError`).
* **Testability**: Decoupled headless architecture verified by 52 deterministic automated unit and integration tests.
